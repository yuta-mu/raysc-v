# RayQ 言語仕様 v1.1

RaySC-V プロジェクト / 2026-10-10

コンパイラ: `rayqc` / ターゲット: RV32IM + custom-0 (Artix-7, ベアメタル)

---

## 方針

- **算術はビット完全に定義し、それ以外はプログラマの責任とする。** 検査用の機構（境界検査、スタック検査）は持たない。
- **可変グローバルは作らない。** グローバルに置けるのは `const`（読み取り専用）だけ。シーン定数や ASCII テーブルは `const` 配列で表す。
- 暗黙の型変換、ポインタ、ヒープ、再帰はない。
- コンパイラは最適化してよい。ただし §11 の条件を守る。
- **未定義（プログラマの責任）とするもの**: 配列の範囲外アクセス、スタックあふれ、代入前の `let` の読み出し、非 `void` 関数での `return` 抜け、再帰呼び出し。ISS と RTL の結果が違っても仕様違反とは見なさない。

## 1. メモリマップ

| アドレス | 用途 |
| --- | --- |
| `0x0000_0000`–`0x0003_FFFF` | 256 KB の共用メモリ。コード、定数データ、スタック |
| `0x1000_0000` | UART 送信 (`sb`) |
| `0x2000_0000` | `cycles` 下位 32bit (`lw`) |

- リセット PC は `0x0000_0000`、初期 `sp` は `0x0004_0000` (メモリ末尾、下方伸長)。
- 属性 (R/W/X) は設けない。
- **配置**: アセンブラ/リンカは、スタートアップコードを `0x0000_0000` から置き、続けてその他のコード、定数データ (文字列を含む) の順に配置する。

## 2. 型とレイアウト

| 型 | サイズ | 備考 |
| --- | --- | --- |
| `bool` | 4 B | 値は 0 か 1 |
| `i32` | 4 B | 符号付き 32bit |
| `q16` | 4 B | Q16.16 固定小数点。実数値 = raw × 2⁻¹⁶、範囲 [-32768.0, 32767.99998…] |
| `vec3` | 12 B | `x, y, z: q16`。`v.x` などで読み書きできる |
| `struct` | フィールドの合計 | フィールドは宣言順に隙間なく並べる |
| `[T; N]` | N × sizeof(T) | `N ≥ 1` の整数リテラル。要素は `T` のサイズで連続する |
| `void` | 0 | 関数の戻り値にのみ使える |

- すべての型のサイズとアライメントは 4 の倍数なので、パディングはない。
- 構造体のフィールドには、スカラー、`vec3`、構造体を使える。**配列は使えない。**
- 空の構造体と再帰的な構造体はエラー。
- 配列を持てるのは、ローカル変数とグローバル `const` のみ。

## 3. 算術 (ビット完全、C Golden Model)

```c
#include <stdint.h>

static inline int64_t sx32(uint32_t u) {
    return (u <= 0x7FFFFFFFU) ? (int64_t)u : (int64_t)u - INT64_C(4294967296);
}
static inline int64_t floor_div_pow2(int64_t x, unsigned n) {   /* n in 0..31 */
    int64_t d = INT64_C(1) << n, q = x / d, r = x % d;
    if (r < 0) --q;
    return q;
}
static inline uint32_t q16_mul(uint32_t a, uint32_t b) {
    return (uint32_t)(uint64_t)floor_div_pow2(sx32(a) * sx32(b), 16);
}
static inline uint32_t i32_div(uint32_t a, uint32_t b) {
    if (b == 0U) return 0xFFFFFFFFU;
    if (a == 0x80000000U && b == 0xFFFFFFFFU) return 0x80000000U;
    return (uint32_t)(int32_t)(sx32(a) / sx32(b));
}
static inline uint32_t i32_rem(uint32_t a, uint32_t b) {
    if (b == 0U) return a;
    if (a == 0x80000000U && b == 0xFFFFFFFFU) return 0U;
    return (uint32_t)(int32_t)(sx32(a) % sx32(b));
}
```

- `i32` と `q16` の `+ - *` と単項 `-` は、32bit ラップアラウンド (単項 `-` は `0 - raw`)。トラップはない。
- `i32` の `/` と `%` は上記の RV32M 規定値 (0 方向へ丸め、`x/0 = -1`、`x%0 = x`)。
- `q16` への `/` と `%` はコンパイルエラー。
- シフトは量を `& 31` する。`<<` は論理、`>>` は算術 (`floor_div_pow2`)。
- `q16 * q16` は `q16_mul` (floor 丸め)。`q16 * i32` と `i32 * q16` は下位 32bit の整数積。
- `vec3 ± vec3` は成分ごと。`vec3 * q16` は成分ごとに `q16_mul`。
- **内積 `a <.> b`** は、`q16_mul(ax,bx) + q16_mul(ay,by) + q16_mul(az,bz)` を左から順に 32bit ラップ加算する。
- **型変換** は `q16(i)` (= `i << 16`) と `i32(q)` (= floor で整数部、`sra 16`) の 2 つだけ。

## 4. 演算子

| 優先 (高→低) | 演算子 | 備考 |
| --- | --- | --- |
| 1 | `.` `[]` `()` | 左結合 |
| 2 | 単項 `-` `!` | 右結合 |
| 3 | `*` `/` `%` `<.>` | 左結合 |
| 4 | `+` `-` | 左結合 |
| 5 | `<<` `>>` | 左結合 |
| 6 | `<` `<=` `>` `>=` | 連鎖不可 (`a < b < c` は構文エラー) |
| 7 | `==` `!=` | 連鎖不可 (`a == b == c` は構文エラー) |
| 8 | `&` | 左結合 |
| 9 | `^` | 左結合 |
| 10 | `\|` | 左結合 |
| 11 | `&&` | 左結合、短絡評価 |
| 12 | `\|\|` | 左結合、短絡評価 |

| 演算子 | オペランド型 | 結果 |
| --- | --- | --- |
| `+ -` | `i32` / `q16` / `vec3` (同型) | 同型 |
| `*` | `i32*i32`, `q16*q16`, `q16*i32`, `i32*q16` | `i32` または `q16` |
| `*` | `vec3*q16`, `q16*vec3` | `vec3` |
| `/ %` | `i32`, `i32` | `i32` |
| `<.>` | `vec3`, `vec3` | `q16` |

| `&& \|\|`, `!` | `bool` | `bool` |
| 単項 `-` | `i32` / `q16` | 同型 |

- `if` と `while` の条件は `bool` のみ。
- 配列の添字は `i32` のみ。添字アクセスの結果型は要素の型。
- `vec3` の単項 `-`、構造体・配列・`vec3` の比較は存在しない。

## 5. 字句

- **予約語**: `bool i32 q16 vec3 void const struct fn let if else while for in break continue return true false`
- **整数**: 10 進 `0|[1-9][0-9]*`、16 進 `0x[0-9a-fA-F]+` (`0xFFFFFFFF` まで。raw ビット列として受理する)。
- **q16 小数**: `[0-9]+\.[0-9]+`。`raw = round_ties_to_even(P × 65536 / 10^K)`。浮動小数点は使わず、任意精度整数で計算する。
- **文字**: `'a'`, `'\n'` などで、型は `i32` (ASCII コード)。エスケープは `\n \\ \' \0` のみ。
- **文字列**: `"..."` は `print` の唯一の引数としてのみ書ける。エスケープは `\n \\ \" \0`。
  - 各文字列リテラルは、文字とエスケープをバイト列に変換した後、**末尾に暗黙の `0x00` を 1 バイト付加して** 定数データ領域に置く。
  - 文字列データの直後に別のデータを置くときは、4 バイト境界に揃える。
- **範囲検査**: 単項 `-` と直後の数値リテラルは先に 1 つの定数に畳み込み、その後で範囲を検査する。
  - `i32` は [-2³¹, 2³¹-1]、`q16` は丸め後の raw が同範囲に入ること。
  - したがって `-2147483648` と `-32768.0` は有効、単独の `2147483648` と `32768.0` はエラー。

### リテラルの型

| リテラル | 型 |
| --- | --- |
| 10 進整数 | `i32` |
| 16 進整数 | `i32` (指定した 32bit の raw ビット列) |
| q16 小数 (`1.0` など) | `q16` |
| 文字 (`'a'` など) | `i32` (ASCII コード) |
| `true` / `false` | `bool` |

リテラルにも暗黙の型合わせはしない。`q16` が必要な場所に整数リテラル `1` は書けず、`1.0` か `q16(1)` を使う。

## 6. 文法 (EBNF)

```ebnf
Program     ::= TopLevel* ;
TopLevel    ::= ConstDecl | StructDecl | FuncDecl ;

ConstDecl   ::= "const" IDENT ":" Type "=" ConstInit ";" ;
ConstInit       ::= "-"? (INT_LIT | Q16_LIT | CHAR_LIT) | BOOL_LIT
                  | "vec3" "(" ConstInit "," ConstInit "," ConstInit ","? ")"
                  | IDENT "(" ConstInitList ")"        /* 構造体 */
                  | "[" ConstInitList "]" ;            /* 配列 */

ConstInitList   ::= ConstInit ("," ConstInit)* ","? ;

StructDecl  ::= "struct" IDENT "{" (IDENT ":" Type ",")+ "}" ;
Type        ::= "bool" | "i32" | "q16" | "vec3" | "[" Type ";" INT_LIT "]" | IDENT ;

FuncDecl    ::= "fn" IDENT "(" (Param ("," Param)*)? ")" "->" (Type | "void") "{" VarDecl* Stmt* "}" ;
Param       ::= IDENT ":" Type ;
VarDecl     ::= "let" IDENT ":" Type ("=" Expr)? ";" ;

Stmt        ::= LValue "=" Expr ";"
              | "if" "(" Expr ")" Block ("else" Block)?
              | "while" "(" Expr ")" Block
              | "for" IDENT "in" Expr ".." Expr Block
              | "break" ";" | "continue" ";" | "return" Expr? ";"
              | Expr ";" ;                                       /* 呼び出し式のみ */
Block       ::= "{" Stmt* "}" ;
LValue      ::= IDENT | LValue "." IDENT | LValue "[" Expr "]" ;

Expr        ::= LogicOr ;
LogicOr     ::= LogicAnd ("||" LogicAnd)* ;
LogicAnd    ::= BitOr ("&&" BitOr)* ;
BitOr       ::= BitXor ("|" BitXor)* ;
BitXor      ::= BitAnd ("^" BitAnd)* ;
BitAnd      ::= Equality ("&" Equality)* ;
Equality    ::= Relational (("==" | "!=") Relational)? ;
Relational  ::= Shift (("<" | "<=" | ">" | ">=") Shift)? ;
Shift       ::= Additive (("<<" | ">>") Additive)* ;
Additive    ::= Mul (("+" | "-") Mul)* ;
Mul         ::= Unary (("*" | "/" | "%" | "<.>") Unary)* ;
Unary       ::= ("-" | "!") Unary | Postfix ;
Postfix     ::= Primary ("." IDENT | "[" Expr "]" | "(" (Expr ("," Expr)*)? ")")* ;
Primary     ::= IDENT | INT_LIT | Q16_LIT | CHAR_LIT | BOOL_LIT | STR_LIT
              | ("i32" | "q16") "(" Expr ")"
              | "vec3" "(" Expr "," Expr "," Expr ")"
              | "(" Expr ")" ;
```

### 6.1 意味規則

- **名前**
  - 構造体、関数、`const`、組み込みは単一のグローバル名前空間に属し、互いに衝突できない。
  - ローカル変数、引数、ループ変数は、グローバルの名前とも互いとも衝突できない (shadowing 禁止)。
  - 関数、構造体、`const` は前方参照できる。`fn main() -> void` が必須。
  - `IDENT(args)` は、関数なら関数呼び出し、構造体ならコンストラクタとして解決する。
- **構造体コンストラクタ**: `Name(e1, ..., en)` はフィールドの宣言順に個数と型を厳密に検査する。
- **`let`**: 関数先頭にのみ書ける。初期化子があれば、宣言順に関数入口で評価する。
- **引数**: 読み取り専用 (代入するとエラー)。
- **配列の使用範囲**: 配列型を使えるのは、ローカル変数とグローバル `const` のみ。**構造体のフィールド、関数の引数、関数の戻り値には使えない** (型検査でエラー)。配列同士の代入、配列全体の比較もない。配列の要素は個別に読み書きできる (`const` 配列は読み出しのみ)。
- **`for i in a..b`**: 半開区間 [a, b)、型は `i32`。`a` と `b` は開始時に一度だけ左から評価する。`i` は読み取り専用。
- **`break` / `continue`**: ループの外で使うとエラー。
- **関数の末尾**: `void` 関数は、末尾に到達したら暗黙に `return;` する。非 `void` 関数が末尾に到達した場合は未定義。宣言した戻り値の型と合わない `return` はコンパイルエラー。
- **再帰**: 禁止。再帰呼び出し (相互再帰を含む) を書いたプログラムは未定義で、コンパイラは検出する義務を負わない。
- **グローバル `const`**
  - 型は任意 (スカラー、`vec3`、構造体、配列)。初期値は `ConstInit` の範囲 (リテラルの組み合わせ) に限る。
  - 他の `const` や関数の呼び出しは参照できない。型は厳密に一致し、配列の要素数は `N` と一致する。
  - 実体は定数データ領域に置かれる。関数内からは読み出しのみで、代入するとエラー。
- **評価順序**: 式、引数、コンストラクタ引数は左から右。**代入 `L = R` は、まず `L` の添字を評価してアドレスを決め、その後 `R` を評価し、最後に格納する。** 算術は例外もトラップもない純粋な計算なので、この順序が観測できるのは MMIO 呼び出し (§8) だけである。
- 構造体と `vec3` の代入は、全体の値コピー。

## 7. ABI

- **レジスタ**: `sp` は 4 バイト整列。`ra`、`a0`–`a7`、`t0`–`t6` は caller-saved。`s0`–`s11` は callee-saved。他の関数を呼ぶ関数は、自身で `ra` を退避する。
- **引数**: すべての引数を宣言順に 32bit ワード列へ平坦化する。
  - `i32`/`q16`/`bool` は 1 ワード、`vec3` は 3 ワード (x, y, z の順)、構造体はフィールド順に再帰的に展開する。
  - **先頭 8 ワードを `a0`–`a7` に、残りをスタックに** 積む。引数の途中で分割してよい。
- **スタック引数領域**
  - 呼び出し側は、自フレームの最下部 (`sp+0` から) に、**自身が行う呼び出しのうち最大のスタック引数領域** を確保しておく。確保はプロローグで 1 回だけ行い、呼び出しごとの `sp` の増減はしない。
  - 呼び出し直前に、9 ワード目以降を `sp+0, sp+4, …` の順に書く。
  - 被呼び出し側は、自フレームサイズ F を確保した後、`sp + F + 4k` で k 番目のスタック引数を読む。
  - 呼び出し側のローカル変数やスピル領域は、この領域より上位のアドレスに置く。
- **戻り値**: 平坦化した結果が 8 ワード以下なら `a0` から順に返す。9 ワード以上の構造体は戻り値にできない (エラー)。配列は戻り値にできない。

## 8. 組み込み、カウンタ、停止

| 構文 | 型 | 動作 |
| --- | --- | --- |
| `bprint(b)` | `(i32) -> void` | 下位 8bit を UART へ `sb`。FIFO が満杯なら CPU を自動でストールする |
| `print("...")` | 文字列リテラルのみ | 定数データ上の文字列を、末尾の `0x00` の手前まで `lbu` + `sb` で送信する。終端バイト自体は送らない |
| `cycles()` | `() -> i32` | `0x2000_0000` を `lw` する。内部 64bit カウンタの下位 32bit を返し、ラップする |
| `sqrt(x)` | `(q16) -> q16` | custom-0 (§9) |
| `rcp(x)` | `(q16) -> q16` | custom-0 (§9) |
| `rsqrt(x)` | `(q16) -> q16` | custom-0 (§9) |

- `norm` は組み込みではなく、利用者が `fn norm(v: vec3) -> vec3 { return v * rsqrt(v <.> v); }` と書く。
- `bprint`、`print`、`cycles` を **MMIO 呼び出し** と呼ぶ。MMIO は volatile で、消去や順序入れ替えは禁止する (§11)。
- 区間計測は `cycles()` の差 (`end - start`、32bit ラップ減算)。出力前に値を保存しておくこと。
- `cycles()` の値は、ISS と RTL の一致検証の対象外とする。

### 起動と停止

- **スタートアップ**: リセット解除後、`0x0000_0000` から実行を始める。`sp = 0x0004_0000` として `jal main` し、復帰したら `ebreak` を実行する。
- **`ebreak`** はトラップを起こさず、CPU を永久に停止する。5 段パイプラインでは次の規則に従う。
  1. 有効な `ebreak` が EX 段に到達したら、新規フェッチを止め、後続の命令を kill する (`reg_we = 0`、`mem_we = 0`、UART 送信なし)。
  2. `ebreak` より前の命令は、WB まで正常に完了させる。
  3. `ebreak` が WB でコミットされたときに停止する。停止 PC は `ebreak` 自身のアドレス。
  4. 先行する分岐・ジャンプで破棄される `ebreak` は、停止要求を出さない (分岐の解決が EX より後になる実装では、解決後に有効と確定した `ebreak` だけが規則 1 の対象になる)。
  - 単一サイクルコアでは、命令の実行完了時に停止する。
- **停止時のカウンタ**: `ebreak` のコミットで、内部の `cycles`（64bit）と `instret`（64bit）を凍結する。テストベンチは停止後に両方の最終値を読む。`ebreak` は `instret` に数えない。

## 9. custom-0

```c
/* sqrt: x <= 0 -> 0,  x > 0 -> floor(sqrt((uint64)x << 16)) (x は raw 値) */

static inline uint32_t q16_rcp(uint32_t x_raw) {
    if (x_raw == 0U) return 0x7FFFFFFFU;
    const int64_t x = sx32(x_raw), num = INT64_C(1) << 32;
    int64_t q = num / x, r = num % x;
    if (x < 0 && r != 0) --q;                       /* 負の分母の floor 補正 */
    if (q >  INT64_C(2147483647))  return 0x7FFFFFFFU;
    if (q < -INT64_C(2147483648))  return 0x80000000U;
    return (uint32_t)(int32_t)q;
}
/* rsqrt: x <= 0 -> 0,  それ以外は rcp(sqrt(x)) */
```

| 命令 (opcode `0x0B`, R-type) | funct3 | funct7 | rs2 | 動作 |
| --- | --- | --- | --- | --- |
| `qmul rd, rs1, rs2` | 0 | 0 | 値 | `q16_mul` と同一ビット |
| `qsqrt rd, rs1` | 2 | 0 | `x0` | `sqrt` と同一ビット |
| `qrsqrt rd, rs1` | 3 | 0 | `x0` | `rsqrt` と同一ビット |
| `qrcp rd, rs1` | 4 | 0 | `x0` | `rcp` と同一ビット |

## 10. サンプル

```rust
const T_EPS: q16 = 0.0039;
const NO_HIT: q16 = -1.0;
const RAMP: [i32; 4] = [' ', '.', '*', '#'];     // グレースケール用 ASCII テーブル

struct Ray    { o: vec3, d: vec3, }
struct Sphere { c: vec3, r2: q16, }

fn to_byte(q: q16) -> i32 {
    let v: i32;
    if (q <= 0.0) { return 0; }
    if (q >= 1.0) { return 255; }
    v = i32(q * 256.0);
    if (v > 255) { v = 255; }
    return v;
}

fn write_pixel(c: vec3) -> void {
    bprint(to_byte(c.x));
    bprint(to_byte(c.y));
    bprint(to_byte(c.z));
}

// Ray (6 ワード) は a0-a5、Sphere (4 ワード) の先頭 2 ワードは a6-a7、残り 2 ワードはスタック
fn hit_sphere(r: Ray, s: Sphere) -> q16 {
    let oc: vec3;
    let b: q16;
    let k: q16;
    let disc: q16;
    oc = r.o - s.c;
    b = oc <.> r.d;
    k = (oc <.> oc) - s.r2;
    disc = (b * b) - k;
    if (disc < 0.0) { return NO_HIT; }
    return -b - sqrt(disc);
}

fn main() -> void {
    let r: Ray = Ray(vec3(0.0, 0.0, -5.0), vec3(0.0, 0.0, 1.0));
    let s: Sphere = Sphere(vec3(0.0, 0.0, 0.0), 1.0);
    let col: vec3;

    print("P6\n1 1\n255\n");
    if (hit_sphere(r, s) > T_EPS) { col = vec3(1.0, 0.5, 0.0); }
    else                          { col = vec3(0.0, 0.0, 0.0); }
    write_pixel(col);
}
```

期待出力は `P6\n1 1\n255\n` に続く 3 バイト `FF 80 00`。`RAMP` は `RAMP[i]` で読める (`i` が 0..3 の範囲にあることはプログラマの責任)。`void` 関数の末尾の `return;` は省略できる (§6.1)。

## 11. コンパイラの最適化と準拠条件

コンパイラは、インライン展開、定数畳み込み、レジスタ割り当て、命令スケジューリングなどの最適化を行ってよい。ただし、すべての最適化レベル (`-O0`〜`-O3`) と、`custom-0` 命令やアクセラレータの使用の有無にかかわらず、次を守る。

1. **算術結果は §3 と §9 の定義とビット単位で同一**であること。
2. **UART に出力されるバイト列は同一**であること。
3. **MMIO 呼び出し (`bprint`、`print`、`cycles`) の実行回数と順序を変えない。** MMIO 呼び出しは並べ替えの壁として扱い、他の命令をその前後に越えて移動しない (`cycles()` で測る区間の意味を保つため)。
4. 未定義とされる動作 (方針の節) に依存した最適化の結果は、保証しない。
5. **置き換えの条件**: 算術を `custom-0` 命令に置き換えるのは常に許される (§9 が同一ビットを定める)。ライブラリ関数をアクセラレータの呼び出しに置き換えるのは、元の関数のソフト実装と同一ビットの結果を返す場合に限る (アクセラレータの仕様は別紙)。

同じプログラムは、どの構成でも同一の PPM を出力する。これを、すべての測定結果の正しさの判定基準とする。

## 付録: 最小限の検証項目

| 項目 | 内容 |
| --- | --- |
| 算術 | `q16_mul` の負数 floor、`i32_div`/`rem` の特殊値、シフト量のマスク、単項 `-` の `INT_MIN` |
| `rcp` | 0、±1、-65536、INT_MIN、割り切れない負の値 |
| `<.>` | 3 積を個別に floor して加算した値が、C、ISS、RTL (`qmul` + `add`) で一致すること |
| ABI | 8 ワードをまたぐ引数 (`hit_sphere`)、スタック引数の参照、8 ワード戻り値、スタック引数領域がローカルと衝突しないこと |
| リテラル | `-2147483648`、`-32768.0`、丸めで 2³¹ に達する小数 (エラー)、`q16` の引数に整数リテラル (エラー) |
| 構文 | `a == b == c` と `a < b < c` が構文エラー、構造体フィールドや引数に配列型を書くとエラー |
| 文字列 | `print` が末尾の `0x00` で止まり、後続データを出力しないこと |
| 停止 | `jal main` 直後の `ebreak` が止まらないこと、`main` 復帰後に止まること、停止後に UART 出力が増えないこと、最終 `cycles` と `instret` を回収できること |
| 最適化 | `-O0`〜`-O3` と `--accel` の全組み合わせで、PPM が golden と 1 バイトも違わないこと |

# RaySC-V SW：Codexと進める作業指示・修正リスト・実装リスト

作成日：2026-10-09。対象：大学の6人チームによるRV32IMコア・独自命令・アクセラレータ・専用コンパイラの協調設計。ユーザーの担当はSW。

この文書は作業案であり、チームが確定した言語仕様ではない。優先度A＝基準実装・結合のために先に行う、B＝基準版の完成後に行う、C＝測定結果と残り時間で判断する。既存CSVのP0〜P3は開発フェーズなので、ここでの優先度とは区別する。

## 現在の実装順序（2026-10-09更新）

ユーザーの方針により、本番向けC++版を先に完成させ、その後に同じ処理をCへ移す。完成範囲は、固定シーン・直接照明・硬い影・最大2回の鏡面反射。C++の段階で構造体・通常関数・固定長配列・ループに整理し、C移植時の設計変更を減らす。

具体的な順序と完成条件は [C++版完成までのロードマップ](CPP_ROADMAP.md) を参照する。以下にある「C基準版から先に実装する」という順序は、この更新で置き換える。D項目の未合意仕様、既存のC++教材版を保持する方針、F/I項目の完了条件は引き続き有効とする。F/Iのチェックは実装と検証が完了してから更新する。

次に着手する項目はロードマップのCPP-00とする。当面の実装順序はロードマップを優先し、以下の「最初の作業」とF/I一覧は関連する作業内容の参照として使う。

開発方針：
- 本番の数値表現は32bit整数とQ16.16。float/doubleを導入しない。
- 基本の球交差・法線・背景を先に確立する。直接照明、硬い影、最大2回の完全鏡面反射は追加候補とする。
- 基準版は固定シーン・固定カメラ・画素中央1サンプル・乱数なしを基本案とする。
- ガラス、煙、Perlin、画像テクスチャ、被写界深度、モーションブラーの本番採用は後回し。既存ファイルを直ちに削除する意味ではない。
- BVHは多数物体での実測を見て採用する。少数物体の最初の基準版は総当たりでよい。
- 学習用C++の再帰・仮想関数・shared_ptr・ヒープ確保は、NESV版では固定長配列・識別番号・ループへ置き換える。
- 数学の基準は「RaySC-V 言語仕様（ドラフトv0.3）」と、チームが後から合意した修正。ただし、この文書に挙げた矛盾を独断で解釈して正式仕様にしない。
- ループ構文をC形式にしたいという希望はあるが、コンパイラ班との合意前に文法を変更しない。
- 本番のRV32IMコードで64bit型やランタイム補助関数を利用するかは、チームの制約と生成コードを確認する。検証用ホスト計算の広い精度は別に扱い、本番へ混入させない。
- 性能比較は同じシーン、画像サイズ、描画機能、サンプル数、数値仕様で行う。機能削減による軽量化と独自命令による高速化を分ける。
- 自作CPUの性能はRTLカウンタや実機で測る。ホストの実行時間やQEMUの経過時間を自作CPUのサイクル数として扱わない。
- 関係のないHW・コンパイラコードや他の人の未コミット変更は編集しない。必要な変更は理由と対象を示す。共有ブランチへのpushやメンバーへの連絡は、別途指示があったときに行う。

最初の作業：

## 2. 調査済みの現状と検証範囲

- 添付の`sw.7z`を確認した。主な対象は`sw/raytracer/cpp/`。現在のCodex環境では同じパスや同じ版とは限らないので、最初に照合する。
- `main.cpp`：多数のランダム配置の球、材質、散乱、背景を描く。設定は384×216、100 samples/pixel、最大深さ50。
- `ppm.cpp`：少数の球、金属・ガラスを含む別の描画エントリ。単なる不要ファイルとは扱わない。
- `week2.cpp`：BVH・箱・動く球・煙・画像・Perlinなどを含むシーン。幅、サンプル数、深さを引数で変更できる。
- `week1.cpp`：Hello World。描画機能ではない。保存用途を確認してビルド対象から外せる。
- 2026-10-09の調査では、`main.cpp + fpm.cpp`と`week2.cpp + fpm.cpp`をホストのg++、C++17でビルドできた。
- `main.cpp`の検証用コピーだけを16×9、1 sample/pixel、最大深さ3へ変更し、未定義動作検出を有効にして2回実行した。この条件では検出エラーなく正常終了し、PPMの画素数・0〜255の値域・2回の出力一致を確認した。全入力の安全性や物理的正しさを保証する検証ではない。
- `week2.cpp`は添付に`earthmap.jpg`がないため起動時に停止した。画像を使うシーンの実行は未検証。
- この添付版について、RV32IM・QEMU・自作RTL上のレイトレーサー実行、独自命令との一致、C基準版・NESV版との画像一致は未確認。
- CSVのSW-01・SW-02は「試作あり、完了条件の整備が必要」と評価する。正式なタスクの完了は、コード量ではなく完了条件と実行結果で判定する。

## 3. 先に合意したい仕様

「推奨」は提案であり、合意前の正式仕様ではない。該当項目だけを決定待ちにし、独立した修正は進める。

| ID | 優先度 | 問題・確認事項 | 合意すべき内容 |
|---|---|---|---|
| D-01 | A | 現行`fpm_mul`はゼロ方向、v0.3 §4.2は負の無限大方向への丸め | v0.3のFloorを採用するか確認し、C・NESV・RTLに同じテストを渡す。raw値で`-1 × 1`は現行0、Floorでは-1になる |
| D-02 | A | §4.2は内積の積和後に1回丸める。§8.2は`qmul`3回＋加算で矛盾 | 推奨は§4.2に合わせ、非加速版も各積を丸めず合計して最後に丸める。raw値`a=(32768,32768,32768), b=(1,1,1)`は後丸め1、個別丸め0 |
| D-03 | A | `rcp`・`rsqrt`の±2 LSBという誤差範囲だけでは、出力が一意にならない | 全バックエンドが同じraw値を返す規則・アルゴリズム・テストベクトル。ゼロ、負数、表現範囲外の扱いも決める |
| D-04 | A | C/C++の符号付きオーバーフロー、負数シフト、中間積和の範囲と「UBなし」の整合 | unsigned演算・ワード分割などでビット規則を表現する。3個の32bit符号付き積の合計は、符号付き64bitにも収まらない場合があるため規則と実装を決める |
| D-05 | A | 現行`fpm_sqrt`は負数入力を仕様どおり扱わない | v0.3の`x<0 → 0`に合わせる。正値では整数平方根の定義を確認する |
| D-06 | A | NESVはq16の`/`禁止。現行C++には多数の`fpm_div`がある | 基準C版とNESV版で対応する演算手順を決める。`qmul(a,rcp(b))`への置換は丸めが変わるので、既存の除算と同一だと仮定しない |
| D-07 | A | 配列要素がすべて4byte境界という記述と、`[u8;4]`が4byteという例が矛盾 | 要素のストライドと配列全体のパディングを区別し、特にRGBフレームバッファのレイアウトを決める |
| D-08 | B | 小数リテラルの最近接丸めの同距離時、カウンタ差分、RGBパック順などが不足 | 境界値の丸め・32bit周回・`bprint_rgb`のR/G/Bビット位置・出力形式を決める |
| D-09 | C | `for`をC形式にしたい希望がある | コンパイラ班との相談項目。現在の移植を独自の未合意文法で始めない |

`qrnd`はv0.3に記載されているが、今回の乱数なし基準版の必須機能にはしない。将来採用する場合は、種・状態更新・呼び出し順・リセット条件を別途定義する。

## 4. 修正リスト：既存コードを整える

### A：基準づくりと、使用していない計算の削減

- [ ] **F-01 現状を再現できる形で記録する**〔SW-01／SW-02〕
  - 現在のコミット・未コミット差分、3つの描画エントリのビルド方法、入力・設定・出力先を記録する。
  - 小さい描画条件を使い、出力PPMとハッシュを保存する。設定変更が必要なら検証用コピーか既存の設定機構を使う。
  - 完了条件：他のメンバーが手順どおりに同じ条件を実行できる。元の状態で失敗するケースも記録する。

- [ ] **F-02 単色シーンの不要なUV計算を省く**〔SW-02〕
  - 対象：`sphere.h`の`sphere::hit()`から呼ぶ`get_sphere_uv()`。
  - 現行の`main.cpp`・`ppm.cpp`の材質は画像UVを必要としない。シーン設定で無効化するか、必要な材質でのみ計算する。
  - `week2.cpp`の画像テクスチャ経路に必要なUVを消さない。分岐・設計変更は小さくする。
  - 完了条件：同じビルド・描画条件の単色シーンで画素値が一致し、UV計算が呼ばれない。UV有効経路は小さい入力で別に確認する。

- [ ] **F-03 ぼけなしカメラで乱数生成を省く**〔SW-02〕
  - 対象：`camera.h`の`get_ray()`。`lens_radius == 0`なら`random_in_unit_disk()`を呼ばず、原点とオフセットを直接設定する。
  - レイ時刻の乱数が必要な動的シーンとは区別する。
  - 完了条件：ぼけなし経路でディスク乱数生成が0回、方向と原点が期待どおり。ぼけあり経路の動作を保つ。
  - 注意：乱数の消費順が変わるので、既存の確率的シーンの画像ハッシュ一致は要求しない。変更を記録して基準を更新する。

- [ ] **F-04 完全鏡面で乱数生成を省く**〔SW-02〕
  - 対象：`material.h`の`metal::scatter()`。`fuzz == 0`なら`random_in_unit_sphere()`を呼ばない。
  - 完了条件：既知の入射ベクトル・法線から期待する反射方向が得られ、粗さ0の経路で乱数を消費しない。粗さありの経路は維持する。
  - 注意：F-03と同じく、乱数列の消費位置が変わる。

- [ ] **F-05 固定小数点の意味を合意仕様に揃える**〔SW-01、D-01〜D-05に依存〕
  - 対象：`fpm.cpp`、`fpm.h`、`vec3.h`、および新しいC基準関数。
  - 乗算のFloor、積和後に1回丸める内積、32bitラップ、負数平方根、例外入力を揃える。
  - 完了条件：合意したテストベクトルにビット一致し、C/C++の未定義動作に依存しない。数値仕様変更で画像が変わった場合は旧画像と区別する。

- [ ] **F-06 移植前提の除算・正規化・球交差を整理する**〔SW-01／SW-02、D-03／D-06に依存〕
  - q16除算を使う場所と、その目的を列挙する。逆数の再利用などは入力の不変性を確認して適用する。
  - 固定小数点では正規化した方向でも`dot(d,d)`が厳密に1とは限らない。球交差の係数を独断で1へ置き換えない。
  - 教材の大きな座標や巨大な床用球を無条件に移さず、中間値の範囲を確認する。
  - 完了条件：CとNESVで同じ演算手順が表現でき、境界・ゼロ方向・接線付近を含む確認がある。

  - 粗さ0の反射のみ。反射方向、色の減衰、累積色をループ内で管理する。
  - 「2回」は反射を最大2回、その先の表面または背景を評価する意味とし、レイ区間数・終了規則を文書化する。
  - 完了条件：再帰・乱数を使わず、鏡を向かい合わせても上限で終了する。

- [ ] **I-08 マイクロベンチマーク群**〔SW-03、I-01と利用可能なコンパイラに依存〕
  - CSVの`bench_add`、`bench_qmul`、`bench_dot3`、`bench_sphere`を小さい固定入力で用意する。
  - 先にCで期待値を作り、NESV版を追加する。必要に応じて`sqrt`・`rsqrt`・`rcp`も評価する。
  - 最適化で計算全体が消えないよう、実際の入力と出力チェックを設計する。volatileだけに依存して本来の演算を歪めない。
  - 完了条件：出力一致、サイクル数、命令数が同じ条件で取れる。MMIO計測の区間とオーバーヘッドを記録する。

- [ ] **I-09 NESV版レイトレーサーと画像差分確認**〔SW-04、I-03／CMP-04に依存〕
  - 最小C版から移植する。C++の豊富なシーンをまとめて移植しない。
  - 基準C版とNESV版で演算順、固定小数点規則、画像出力の意味を一致させる。
  - P3とP6などファイル形式が異なる場合は、復号したRGB画素列で比較する。
  - 完了条件：Microから順に画像が一致し、不一致は最初の画素と必要な中間値まで追跡できる。

- [ ] **I-10 構成別の自動評価**〔TOL-03、I-08／I-09／必要なHWに依存〕
  - 基準RV32IM、zbb、math、dot3と、利用可能な最適化設定を組み合わせる。未実装の組合せは未実施として記録する。
  - commit、仕様版、コンパイラ設定、シーン、解像度、サンプル数、機能、画像一致、cycles、instret、可能ならfmax・回路規模を記録する。
  - 計算区間と画像転送を含む区間を分ける。DMAによる重なりを単純な時間の和として扱わない。
  - `dot3`がポインタを取る構成では、入力のメモリ配置・書き戻し・呼び出し負荷もアプリ全体の評価に含める。
  - 完了条件：同一条件の比較表を再生成でき、結果の出所が追える。クロックが異なる構成ではサイクル数に加え時間も比較する。

### C：基準版の結合が終わった後

- [ ] **I-11 固定4点サンプリング**
  - 乱数なしで画素内の4位置を評価する。一次レイ数は1点の4倍になるので、展示時間を測って採用する。
  - このモード用の正解画像を別に保存し、1点の結果と同じ評価条件として比較しない。

- [ ] **I-12 静的BVHと配列による走査**
  - 物体数を増やして総当たりとの実測を行い、必要なら採用する。
  - 構築はホストで行う案を優先し、ノードを固定配列へ格納する。NESVでは再帰・ポインタを使わず、必要なら上限付き明示スタックを用いる。
  - 完了条件：最近傍・同距離の選択規則・境界処理が総当たりと一致し、利用メモリと実行時間の改善が確認できる。

## 6. 本番へ持ち込む機能の案

| 扱い | 機能 |
|---|---|
| 基準版で必須 | Q16.16演算、球交差、法線、固定カメラ、背景、PPM、固定シーン、画像差分、測定 |
| 基準版の完成後に優先 | 直接照明、硬い影、完全鏡面反射 |
| 効果と時間を見て追加 | 固定4点サンプリング、整数格子の市松模様、静的BVH |
| 当面は本番対象外 | ガラス、粗い金属、確率的多重散乱、被写界深度、モーションブラー、画像テクスチャ、Perlin、煙、複雑な箱・変換 |

関数やファイルが存在するだけで描画時間が増えるとは限らない。実際に呼ぶ処理の削減と、リンク結果・依存関係の削減を区別する。除外機能の既存コードは、学習・比較に使える形で保持する。
